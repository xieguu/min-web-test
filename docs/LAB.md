# MIN LAB 使用与测试入口

入口：`http://127.0.0.1:3000/lab`。注册后由管理员授予 LV2 或 LV3，再登录进入。页面顶部可以选择模式和练习身份。账号等级与练习身份分开，切换 Alice / Bob 不会改变账号等级。

## 1. SQL 注入：商品搜索

- 请求：`GET /api/lab/search?mode=vulnerable&q=KEYWORD`
- 正常结果：3 个已上架商品；关键词“笔记本”匹配 1 个商品。
- 测试输入：`%' OR 1=1 --`
- 漏洞现象：返回 4 个商品，其中包含 `LAB_SQLI_FOUND`。
- 切换 `mode=fixed`：同一输入返回空列表，输入 `%` 仍只返回 3 个已上架商品。

这一场景直接对 `lab.sqlite` 执行查询。`users`、`articles` 和 `files` 属于另一个数据库，不在该练习连接中。

## 2. 对象越权：私人笔记

练习身份由 `POST /api/lab/actor` 设置，JSON 为 `{"actor":"alice"}` 或 `{"actor":"bob"}`。该身份保存在服务端会话中。

| 当前身份 | 笔记编号 | 漏洞模式 | 修复模式 |
| --- | --- | --- | --- |
| Alice | 1001 | 200，自己的笔记 | 200 |
| Alice | 1002 | 200，Bob 的笔记，含 `LAB_IDOR_FOUND` | 403 |
| Bob | 1002 | 200，自己的笔记 | 200 |
| Bob | 1001 | 200，Alice 的笔记 | 403 |

请求格式：`GET /api/lab/notes/1002?mode=vulnerable`。在 HTTP 代理中改路径中的编号，比较响应即可。

## 3. 存储型 XSS：留言预览

提交到 `POST /api/lab/messages`，正文：

```json
{"body":"<script>document.body.append('XSS 已执行')</script>"}
```

打开 `/api/lab/messages/preview?mode=vulnerable` 或查看页面内的留言预览，末尾会出现独立的 `XSS 已执行` 文字。刷新后仍会执行，说明输入经过了持久化。

切换为 `mode=fixed` 后，原来的脚本作为文本展示。预览运行在具有独立源的 sandbox iframe 内：脚本可以改变自己的页面，不能访问父页面的 DOM、Cookie 或存储。此场景使用 DOM 标记验证执行，不依赖弹窗。

## 4. 基础业务测试入口

| 功能 | 测试方向 | 正常预期 |
| --- | --- | --- |
| 注册、登录 | 重复邮箱、密码长度、错误密码、退出后的会话 | 400 / 409 / 401；退出后不再有身份 |
| 内容 | 未登录发布、改他人内容、删除后读取 | 401 / 403 / 404 |
| 评论 | 空内容、超过 2000 字、HTML 输入、删除他人评论 | 400、转义显示、403 |
| 文件 | multipart 字段名、缺少文件、2 MiB 限制、中文名、下载字节一致性 | 400 / 413；成功文件原样下载 |
| 文件权限 | 账号 A 上传，用账号 B 携带相同文件 ID 下载 / 删除 | 403 |
| 写入校验 | 去掉 `X-Requested-With: min-web-test` 后重放写请求 | 403 |

这些业务入口按正常权限和输入规则运行；预置漏洞集中在 `/api/lab/`。

## 5. 记录与重置

- `GET /api/lab/events` 返回当前登录账号最近 30 条练习请求：时间、方法、路径、练习身份、模式、状态码。
- 路径不含查询参数，记录不存请求正文、密码或 Cookie；全站最多保留 500 条。
- LV3 管理员使用页面底部的重置表单，或向 `POST /api/lab/reset` 发送 `{"confirmation":"RESET"}`。LV2 请求该接口返回 403。
- 重置恢复商品与笔记，清空后重新生成初始留言和练习记录，当前会话练习身份恢复为 Alice。
- 练习数据为本站共享数据；账号、文章、评论、文件属于 `site.sqlite`，不会随练习重置。

[HTTP 请求样例](requests.http) 可在支持 `.http` 的客户端打开，也可复制给自己的代理或脚本。将 `COOKIE_VALUE` 替换成注册 / 登录响应里 `min.sid=` 后面的值。
